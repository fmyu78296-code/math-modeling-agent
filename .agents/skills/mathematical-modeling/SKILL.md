# mathematical-modeling

## 输入和执行边界
从项目根读取 docs/protocol.md 和当前任务 JSON。需要上游产物存在且已验收；只写任务 output_dir。按当前任务范围执行，不自行创建 Agent。以下输出均相对 output_dir。

## 执行步骤
1. 从逐问需求与已选方案出发。符号表定义变量/参数、范围、索引、维度、单位和来源，区分固定值与待估值。
2. 每个假设说明必要性、领域理由、可能偏差及可检验方式；来自文献的公式、参数或边界条件要对照 claim_source_map.csv 和 model_transfer.md 核查原始条件与本题差异，不可把方便求解直接当作事实。
3. 给出目标函数及现实含义、所有等式不等式、变量域、初边值、状态转移或观测方程；无需优化的任务不要虚构目标约束。
4. 推导关键公式与估计式，说明识别条件、正则化或先验。检查单位、符号、边界、退化情形、无解/无界及冗余约束。
5. 明确“模型”和“求解算法”区别。针对优化给小规模可行例和冲突约束例；针对数值方程检查守恒及步长；针对回归检查秩。
6. 把公式对应到将实现的函数、参数和测试。模型更改必须同步代码、实验配置和文稿，不使用只存在于论文的模块。

## 输出与验收
交付 model.md、symbols.csv、model_checks.md。记录输入来源、处理规则、实际命令、未完成项。按协议向总控返回产物及真实状态；无关键输入时返回 blocked。输出可追溯、单位一致、内容覆盖 acceptance 后才能标 completed。
