# experiment-analysis

## 输入和执行边界
从项目根读取 docs/protocol.md 和当前任务 JSON。需要上游产物存在且已验收；只写任务 output_dir。按当前任务范围执行，不自行创建 Agent。以下输出均相对 output_dir。

## 执行步骤
1. 读取预设计划、参数、数据划分和运行日志。明确每个指标方向、单位、定义和适用范围。
2. 预测报告 MAE/RMSE 等，零目标时谨慎 MAPE；分类关注不平衡及阈值来源；聚类兼顾稳定性和领域意义；优化报告可行性、目标、界及时间。
3. 确保候选用相同信息和切分。测试集只作最终评估，不据其挑方案；发现问题后标明新的探索轮次。
4. 敏感性选有领域意义的参数和扰动；稳健性用适当分组/时间抽样或噪声；组合模型可消融。每种实验需真实运行，不适用则解释。
5. 区分样本内性能、验证性能和最终测试，不用单次差异声称统计显著。随机实验重复种子并报告分散程度。
6. 解释改进幅度、误差区域和反常点，不仅列分数。失败、退化和资源不足保留记录。
7. 审查输入哈希、实现和配置一致性；结论附证据路径，不能将静态检查等同于科学有效性。

## 输出与验收
交付 metrics.json、comparison.csv、sensitivity.csv、experiment_report.md。记录输入来源、处理规则、实际命令、未完成项。按协议向总控返回产物及真实状态；无关键输入时返回 blocked。输出可追溯、单位一致、内容覆盖 acceptance 后才能标 completed。
