# problem-analysis

## 输入和执行边界
从项目根读取 docs/protocol.md 和当前任务 JSON。需要上游产物存在且已验收；只写任务 output_dir。按当前任务范围执行，不自行创建 Agent。以下输出均相对 output_dir。

## 执行步骤
1. 完整阅读正文和附件，建立文件清单；PDF 表格和图中的单位需核对，OCR 不确定处明确标记。
2. 逐问提取背景、研究对象、目标、已知条件、输出格式、限制、评价标准和隐含要求。对每问写输入、输出、依赖与可独立部分，建立有向依赖图。
3. 分别识别预测、分类、聚类、评价、估计、优化、调度、图论、时序、机理和仿真；混合题允许多标签。
4. 提取决策/状态变量、参数、时间空间结构、随机性、边界及数据单位。区分题目事实、解释推断和暂定假设。
5. 列出最少所需数据、关键缺失和可检验假设。缺正文或关键附件时返回 blocked；没有依据不得补造数据。
6. 输出逐问需求表与验收条件，检查每项输出均有来源和负责阶段，再交数据处理。

## 输出与验收
交付 problem_analysis.md、task_breakdown.md、assumptions.md。记录输入来源、处理规则、实际命令、未完成项。按协议向总控返回产物及真实状态；无关键输入时返回 blocked。输出可追溯、单位一致、内容覆盖 acceptance 后才能标 completed。
