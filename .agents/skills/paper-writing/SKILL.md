# paper-writing

## 适用范围与依据
先按 AGENTS.md 确定本次写作范围。整篇初稿或实质性修订时使用本 Skill；仅转换 Word/LaTeX、调整版式或替换现成图片时，保留原内容，按局部任务规则处理，不重新启动研究与全文审阅。正式分派的子任务遵守 docs/protocol.md 和任务 JSON，只写指定 output_dir；不自行创建 Agent。

当届官方格式规范和模板（如 2026 年附件 2、3）决定版式与必要页面；`templates/paper.md` 和 [写作框架](references/writing-framework.md)只帮助安排论证，不是官方模板。写 2026 C 题时再读 [C 题逐问写作提示](references/c-eeg-outline.md)，其他题不加载。先读题面、现有论文、模型与实验产物，再决定哪些章节需要写或改。当前用户希望成稿约 30 页；按官方模板排版后的 PDF 估算篇幅，以实证内容支撑，不靠重复背景、公式或图片凑页。

## 写作决策
1. 建立“题目要求 → 本文回答 → 模型/实验 → 关键图表或数值 → 证据路径”的简表，找出空白。先写有实证支撑的结果与逐问解释，再写方法、引言和摘要；不把算法清单按顺序改写成论文。
2. 每个实质性子问题说明：为什么这样建模、核心假设与变量、关键推导或约束、如何估计/求解、得到什么结果、与基线或备选方案相比如何、在哪些情形失效、该结果怎样回答题目。按 [写作框架](references/writing-framework.md)展开到读者可复现且能判断结论的程度；无需为凑页数重复背景或堆砌公式。
3. 结果段落先给明确发现，再引用带单位和样本范围的数值/图表，解释其含义与限制。将失败、弱收益和不确定性写进分析，不把负结果藏在附录，也不把训练表现写成泛化能力。摘要用真实结果压缩逐问答案、方法和可信创新点，最后完成。
4. 与 visualization Skill 协调正文图片：先确定每图要回答的一个问题、插入位置和目标栏宽，再生成图；正文优先保留少量能承载比较或机制的主图，相似条件的重复曲线可组成易读分面图或移至附录。每图在正文有引入、编号图题和一段解释，不能只插图不分析。作图规范见 `../visualization/references/paper-figures.md`。
5. 新写或改动模型主张、数值和引用时，核对相应代码/实验输出、`claim_evidence.csv`、文献 `references.csv` 与 `claim_source_map.csv`；对本次新增引用核对来源、定位和支持范围。区分文献结论、项目实测、模型假设与推断；不编造实验、显著性、获奖等级或临床效果。纯排版任务不重审未改动的主张。
6. 交付前按本次范围做一次编辑检查：逐问是否得到清楚回答，标题层级与段落衔接是否顺畅，摘要数字和正文结果是否一致，图表是否可读且被解释，引用是否对应。发现问题只修正并复查受影响处；通过即结束。最终候选包的独立提交审查由总控在相应阶段另行安排。

## 输出与验收
完整论文任务交付可编辑正文及实际生成的图表、参考文献和必要证据映射，注明文稿版本、使用的结果版本与尚未完成处。局部修订只交付用户要求的文件和相关检查结果，不为满足清单制造空文件。正式子任务的产物、命令与状态按 docs/protocol.md 返回。
