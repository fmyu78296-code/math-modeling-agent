# data-processing

## 输入和执行边界
从项目根读取 docs/protocol.md 和当前任务 JSON。需要上游产物存在且已验收；只写任务 output_dir。按当前任务范围执行，不自行创建 Agent。以下输出均相对 output_dir。

## 执行步骤
1. 先记录文件哈希、格式、表名、维度、字段含义、单位、时间范围和唯一键。保留原始副本。
2. 统计缺失、重复、非法类型、无穷值、异常范围及分布；给出各规则影响的行数，不把极端值默认当错误删除。
3. 先确定训练/验证/测试划分，再拟合插补、缩放、编码、降维及特征选择；所有拟合只用训练部分。
4. 时间序列不使用未来值插补当前输入；分组对象不能跨集合泄漏；外部数据按真实可用时间对齐。
5. 记录排序、单位换算、聚合和连接键；检查连接前后行数及多对多膨胀。保留剔除原因，能追溯到原始记录。
6. 根据问题制作分布、相关、趋势和类别比例；相关不作因果解释。解释缺失机制和异常处置选择。
7. 输出可重复运行的处理代码与日志；验证重新运行一致、目标不被错误填补、处理后数据满足后续模型契约。

## 输出与验收
交付 data_report.md、data_dictionary.csv、cleaning_log.json、processed.csv、预处理代码。记录输入来源、处理规则、实际命令、未完成项。按协议向总控返回产物及真实状态；无关键输入时返回 blocked。输出可追溯、单位一致、内容覆盖 acceptance 后才能标 completed。
