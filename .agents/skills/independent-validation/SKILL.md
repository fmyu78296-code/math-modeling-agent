# independent-validation

## 输入和执行边界
从项目根读取 docs/protocol.md、当前 review 任务 JSON、赛题、原始附件、上游 result.json、代码、配置、模型、实验及论文。reviewer 只读，不改被审文件、不覆盖运行目录；需要新的计算产物时向总控提出独立复现任务，由总控分配新的 output_dir。以下审阅报告由总控按任务协议保存到 validation/runs/<task_id>/。

## 执行步骤
1. 从逐问交付要求建立核验矩阵：每个关键结论对应题目条件、模型公式、代码位置、输入哈希、实验产物和论文位置。区分“能读取”“能重现”“科学上有支持”三种不同结论。
2. 对核心结果选取可独立核算的小样本、边界情形或汇总项，重新计算并记录所用命令、版本、输入、预期值、实际值和容差。若只能静态审阅，明确未运行；不能把同一函数再次调用当作独立验证。
3. 优化问题逐项核查变量域、容量、时间、路径、守恒及全部题目硬约束，区分可行解、求解器最优性界与启发式结果。预测/分类问题检查样本独立性、训练预处理拟合范围、标签定义、测试集冻结和指标分母。仿真/机理问题检查量纲、数值稳定性、初边值与可识别性。
4. 抽查图表、表格、摘要数字和引用映射是否来自同一版本；检查来源表及模型迁移结论是否足以支持论文语句。对重大主张优先检查，不以无关小错掩盖可行性或数据泄漏问题。
5. 每个发现写严重度、文件与定位、复现步骤、证据、影响和最小修复建议。区分已证实错误、尚待验证的风险和审阅范围外事项；对无发现项只说“在检查范围内未发现”。修复后对受影响结论复核，不能沿用旧报告的通过状态。

## 输出与验收
返回结构化 `validation_matrix`、`findings`、`verified_claims`、`untested` 和结论摘要，由总控保存 `independent_review.md` 并按 docs/protocol.md 生成 reviewer 的 result.json。关键硬约束、数据泄漏或论文主结论存在未解决错误时不得给“通过”。审阅结论需注明静态/实测范围、真实命令和依赖版本；未获得原始数据或代码时返回 partial/blocked，并列出确切缺口。
