# literature-evidence

## 输入和执行边界
从项目根读取 docs/protocol.md、当前任务 JSON、赛题与附件；先读 refs/README.md 和 refs/catalog.csv，核对用户已提供的原始文献，再按任务范围补充检索。researcher 和 solver 只写各自的 output_dir，不改 refs/ 原始文件或 competition/input/；reviewer 只读检查，由总控保存审阅结果。Skill 不能自行创建 Agent。以下输出均相对当前任务 output_dir；跨任务复用时由总控把已验收产物列入下游输入，并核对来源与哈希。

## 执行步骤
1. 先列出逐问需要外部依据的事实、机理、方程、参数范围、算法适用条件和评价方法。对照 refs/catalog.csv 和本地 PDF/HTML/文本，记录已覆盖与待补的主张；小组汇总只当检索线索，不当原文。由未覆盖问题生成中英文检索词及同义词，记录检索日期、查询式、检索平台和筛选理由；不要为了凑引用数量搜索。
2. 优先查原始论文、出版社或 DOI 页面、标准原文、官方数据与软件文档。综述可用于找线索，但关键公式和结论尽量回到原始来源。核对题名、作者、年份、出处、DOI/稳定链接及版本；打不开的来源如实标为未核验。不得编造检索结果、页码、引用或全文访问。
3. 对每个拟引用结论记录可定位位置（页码、章节、公式号或网页小节）、实际可读范围（全文、摘要、元数据）、原文支持的精确含义和限制。只看摘要时仅使用摘要能支持的结论；不把二手转述当成原文证据。原始文件可按赛事及版权规则引用，不整篇复制传播。
4. 提取文献模型的变量、假设、公式、单位、边界条件、数据规模、验证方法和失败情形，与本题附件逐项比较。注明可直接采用、需修改或不适用；文献参数不能未经单位换算和情境校准就填入本题。明确哪些是文献结论、哪些是本项目推导、哪些是待验证假设。
5. 先用文献支持候选与基线的提出，再用本题数据、约束和独立实验选择模型。文献不能替代可行性检查、代码运行、参数估计或测试集评估。没有合适文献时保留可解释基线，并把证据缺口写入局限，不杜撰“经典模型依据”。
6. 建立“论文中的主张/模型决策 → 来源 ID → 定位 → 支持范围 → 本题适配检查”的映射。本地来源沿用 refs/catalog.csv 的稳定 ID；新检索来源使用新 ID，先按 DOI、URL、题名和年份去重。可用 tools/reference_bridge.py 在任务目录生成与合并 references.csv，冲突报告必须人工审阅；脚本只检查匹配和本地哈希，不证明主张。引用格式遵守当届赛事规则；正文编号或引用键须与参考文献表一一对应。赛题附件、项目实验和外部文献分开标记，不用外部文献冒充本项目实测结果。
7. reviewer 对上述记录只读抽查：链接和元数据是否对应、定位能否找到主张、引用是否过度外推、公式/单位是否正确迁移、论文是否漏引或误引。记录无法核实的项及原因，不把静态核对说成文献真伪的全面证明。

## 输出与验收
researcher/solver 交付 search_log.md、references.csv、claim_source_map.csv、model_transfer.md；字段与写法见 templates/literature-evidence.md。若任务只是针对性补证，可依 acceptance 限定产物，但必须保留来源、可读范围、支持范围和未核验状态。在线检索不可用时，记录实际尝试及限制；可使用已提供资料，但未核实资料不能标为已核验。缺失证据若直接影响任务正确性，按 docs/protocol.md 返回 partial 或 blocked，不假装 completed。reviewer 返回带路径、证据与影响的只读审阅意见。所有产物路径、实际命令和局限按协议写入 result.json；不得把计划中的检索记为已执行。
