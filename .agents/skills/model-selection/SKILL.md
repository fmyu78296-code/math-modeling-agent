# model-selection

## 输入和执行边界
从项目根读取 docs/protocol.md 和当前任务 JSON。需要上游产物存在且已验收；只写任务 output_dir。按当前任务范围执行，不自行创建 Agent。以下输出均相对 output_dir。

## 执行步骤
1. 读取题目分析、数据报告、knowledge/model-selection.md，以及 literature-evidence 产出的来源表、主张映射和迁移记录；无可用文献时记录证据缺口。明确样本、维度、机理、约束、噪声、实时性、解释性和剩余预算。
2. 至少列简单基线、主候选和可行备选；任务确实只有一个合理模型时说明依据。逐项写数学思想、公式、输入输出、目标约束、数据要求、资源、优缺点与失败模式。区分文献支持的适用条件、本题独立假设与本题验证结果，不凭引用数量决定模型。
3. 优化题先数学化再选精确求解或启发式；有明确机理优先检验机理加数据修正；不能为复杂而复杂。
4. 预先确定评价指标、划分、调参空间、预算和停止规则。小样本谨慎复杂模型；数据不足不以神经网络填补证据。
5. 仅用验证集选型，冻结后再看测试表现；复杂模型无可靠收益时保留简单模型。报告性能之外的解释和计算代价。
6. 记录被淘汰候选及理由，不删除失败结果。交付选型决策及可复现的实验计划，而非泛泛算法清单。

## 输出与验收
交付 model_candidates.md、selection_decision.md、experiment_plan.md。记录输入来源、处理规则、实际命令、未完成项。按协议向总控返回产物及真实状态；无关键输入时返回 blocked。输出可追溯、单位一致、内容覆盖 acceptance 后才能标 completed。
