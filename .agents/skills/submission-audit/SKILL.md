# submission-audit

## 输入和执行边界
从项目根读取 docs/protocol.md、当前 review 任务 JSON、当届官方参赛/提交规则及其来源、最终论文、代码、数据说明、引用表和拟提交文件清单。reviewer 只读检查，由总控保存报告；不得替用户上传、提交或覆盖定稿。缺规则时先向总控报告需核实事项，不用往届规则或经验填空。以下报告保存于本次 review 的 output_dir。

## 执行步骤
1. 为每条有约束力的要求记录官方来源、发布日期或版本、原文定位、适用范围、截止时间及核验状态。优先使用当届官方通知、赛题附录和提交系统说明；冲突时标记并请求核实，不自行选择有利版本。把“要求”“建议”“项目内部习惯”分开。
2. 以独立生成的最终文件为对象，核对论文格式、页码、图表可读性、公式/编号/交叉引用、中文字体、参考文献编号、匿名与身份信息、文件名和格式。文稿源文件正常不等于导出的 PDF 正常；如能打开 PDF，应实际检查首页、随机内页、末页及含图表页面。
3. 把摘要、正文、结论的每个关键数值与已验收实验产物比对；正文引用与 references.csv、claim_source_map.csv 一一对应。检查代码、配置、运行说明、附件和支撑数据是否齐备，且未把原始资料、敏感信息或旧版本误放进拟提交包。
4. 对拟提交文件制作路径、字节数、SHA256、生成时间、来源运行 ID 和用途清单；检查压缩包可读取、内部路径及文件清单，且论文与支撑材料来自同一冻结版本。仅审核实际存在的候选包，不把“准备生成”写成“已核验”。
5. 输出逐项 `pass/fail/unknown/not_applicable`、证据位置、风险等级和修复责任。无法核实在线系统步骤或提交截止时标为 `unknown`；修复后重新核验受影响文件及哈希。最终结论只能是“交付包检查结果”，不是比赛系统接受或获奖保证。

## 输出与验收
由总控保存 `submission_checklist.md` 和 `submission_manifest.csv`，并按 docs/protocol.md 生成 result.json。报告列出规则版本、已检查的实际文件、未核实项、阻断项和人工复核点。缺当届关键规则或最终候选文件时返回 partial/blocked；存在未解决的阻断项不得标注可提交。此 Skill 只做准备与核验，提交动作需用户明确授权。
